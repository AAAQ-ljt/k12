## 0. 一句话定位

**Nexora 是一个面向 K12 的 AI 通识课教学助手**：以「大模型 + 多模态 + 自适应」为技术路线，
把"一节课"拆成**问（对话问答）、看（教材与动画）、练（游戏化练习与自动批改）、创（绘本/知识页）、温（掌握度与复习）**五个闭环，
并按**小学低 / 小学高 / 初中 / 高中**四个学段切换内容深度、交互形态与激励口径；
学生的每一次学习都会沉淀为掌握度、积分与学习路径上的下一步。

## 2. 智能体设计合理性（25%）

### 2.1 系统架构（一张图讲清）

```
学生端（React 19 + TS + antd v6）     管理端（React + antd）        产品官网（Astro 静态）
        │ HTTP /api（6060）                 │ /api（6061）                 │ 静态托管
        │ WebSocket /ws（6062）             │
        ▼                                  ▼
  nexora-web ────────────────┐    nexora-admin ────────────┐
   Netty WebSocket 流式推送   │    运营/内容/模型配置        │
   ChatClient + 工具回调      │                              │
        │                    ▼                              ▼
        │            nexora-common（领域与基础组件：积分/掌握度/学习路径/知识库/Redis/文件）
        │                    │
        │  MCP（HTTP）       │  MySQL 8 · Redis · Elasticsearch（RAG 向量检索）
        ▼                    ▼
  nexora-mcp（8084，18 个教学工具）—— 教材检索 / 课程课时 / 资源推荐 / 掌握度 / 学习记录
                                      / 知识页 CRUD / 学习路径（查询路线·节点·下一步建议）
```

**设计要点**（评委常问的三点）：

1. **对话与工具分离**：所有"平台事实"（课程、课时、教材、掌握度、学习路径）都不靠模型记忆，而是由 MCP 工具按学生身份查真实库；工具在 MCP 服务独立部署，web 只在提示词里注册"有哪些工具、什么时候用"。
2. **流式与异步分离**：对话走 Netty WebSocket 流式推送（`outputting` 增量 + `done` 全文）；耗时的生成类任务（绘本、动画、学习路径、节点出题）走异步任务 + 进度回轮询，避免阻塞对话。
3. **写入唯一入口**：积分只有一个写入者（`PointAwardComponent`），掌握度只有一个写入者（`KnowledgeMasteryComponent`），学习路径状态只在 `LearningPathComponent` 刷新 —— 避免多处写入导致口径不一致。

### 2.2 大模型调用策略

| 策略 | 实现 | 可演示点 |
|---|---|---|
| 供应商可切换 | `ChatProvider` 抽象 + `ChatProviderRouter`（默认 Bean 跟随配置）：DeepSeek / OpenCode Go 两套实现；`system_config.AI_MODEL.chat_provider` 决定学生端与管理端用哪家，**保存即生效、无需重启** | 管理端「系统设置 → 环境配置」切换后立刻对话验证 |
| 调用参数约束 | 网关兼容性处理：OpenCode Go 要求 `x-opencode-session` 头与专用 User-Agent、`reasoning_effort=low`、`parallel_tool_calls=false`；工具结果回传不带 `name`（修掉网关 400） | 现场演示工具类提问（原先必崩，现已修复） |
| 提示词分层 | ① 平台安全规则 ② 平台事实规则（不得编造课程/人数/掌握度） ③ 学段模板（三层覆盖：Redis → DB → 枚举默认）④ 场景注入（路径节点上下文）⑤ 会话内临时要求 | 管理端「模型与提示词」里改模板、立即生效 |
| 事实约束 | 4 条事实规则 + "学习数据来源规则"：涉及路径/掌握度必须先查工具；学生已提供的信息必须直接引用，禁止回答"没有你的数据" | 问「我下一步该学什么」→ 直接列出真实待复习清单 |
| 工具化教学 | 18 个 MCP 工具，覆盖教材检索、课程课时、资源推荐、掌握度、学习记录、知识页 CRUD、学习路径三件套 | 对话中触发工具（可看服务端日志：MCP 调用与 SQL 命中） |

### 2.3 工具清单（18 个，按用途分组）

| 组 | 工具 |
|---|---|
| 教材 | `searchTextbooks`（书目，按学科**全量**返回）、`getTextbookToc`（目录）、`readTextbookSection`（章节正文） |
| 课程 | `queryCourse`（课程清单/我加入的课程）、`queryLesson`（课时列表与详情） |
| 资源 | `recommendResource`（按学段/知识点推荐官方资源卡片） |
| 学情 | `queryMastery`（掌握度概览）、`saveLearningRecord`（记录学习行为） |
| 学习路径 | `queryLearningPath`（我的路线与未掌握节点）、`queryPathNode`（节点详情+掌握度+下次复习）、`planNextStep`（下一步/薄弱点建议清单） |
| 知识页 | `listKnowledgePages`、`readKnowledgePage`、`createKnowledgePage`、`updateKnowledgePage`、`ingestKnowledgePage`、`createWikiFolder`、`moveKnowledgePage` |

> 每轮对话的可用工具集与提示词里的"能力块"由 web 侧按学生身份注入，模型看不到也伪造不了 `userId` / 学段。

## 3. 多模态交互质量（25%）

### 3.1 文本对话（流式）

- WebSocket 流式推送增量，`done` 推送带**完整全文**（断线重连后不会停在中途）；
- 心跳 20 秒、自动重连（5/10/20/30 秒退避、无限重连）、服务端空闲 120 秒才断开；
- 对话内可直接触发知识页同步、出题、动画讲解等操作。

### 3.2 图像 / 绘本生成

- 学生给主题 → 异步任务生成图文绘本（插图 + 每页旁白），进度轮询可见；
- 文生图供应商可切换（百炼 / 方舟），Key 走环境变量；
- 绘本阅读器：翻页、连播、单页重录、**音色切换**；
- 版权提示条按供应商要求保留在底部（不遮挡内容）。

### 3.3 语音（TTS 已落地，ASR 规划中）

- **朗读**：MiMo TTS，绘本旁白按页合成落盘（同一页同音色复用），支持 9 个预置音色 + 学段默认；
- **音色体系**：免费音色（系统默认 + 小低/小高默认）与可兑换音色分层，服务端做"免费 ∪ 已解锁"门禁，未解锁音色生成/重录都会被拒并给出可操作提示；
- **一次门禁多处生效**：将来 AI 助教朗读回复时继承同一份解锁状态（规划中的支柱 B 会复用这套声线与门禁）。

### 3.4 动画讲解

- 模板化 SVG 动画（概念解析 / 过程演示），由模型选择模板并生成分步脚本，前端按步播放；
- 可讲"算法如何一步步走"（例如冒泡排序的逐步比较与交换）。

### 3.5 视频与文档

- 视频：ArtPlayer + HLS 播放课时视频；
- 文档：Office 类文档走**服务端预转换逐页图**（打开即可阅读、不依赖浏览器插件），PDF 走 JIT 预览；
- 浏览器端 Python（Pyodide）与 Monaco 编辑器支撑编程练习。

### 3.6 内容准确性（评委最容易质疑的一点）

1. **RAG 引用区分**：回答里区分"你的个人知识页 / 平台课程资料 / 教材原文"，来源不同、口径不同；
2. **事实规则**：不得编造课程名、学习人数、难度星级、掌握度；
3. **教材书目全量**：问"我年级有哪些书"时按学科给出完整清单（初中 42 本），并在返回里声明"以下为完整清单"——修复了此前工具截断 20 条导致模型"漏书"的问题；
4. **诚实边界**：系统没有逐题作答记录时，AI 会明确说明"我无法直接告诉你错在哪道题"，而不是编一个错因。

## 4. 教育适配性与实用性（20%）

### 4.1 四学段口径（一张表讲完）

| 维度 | 小学低年级 | 小学高年级 | 初中 | 高中 |
|---|---|---|---|---|
| 导航形态 | 无趣味编程、无动画讲解；含绘本 | 含趣味编程、绘本 | 全量（含动画讲解、学习路径） | 全量 |
| 提示词与用词 | 口语化、句子短、多鼓励 | 口语 + 引导 | 直接、信息密度高 | 直接、接近学科语言 |
| 知识库分层 | 图文/绘本为主 | 图文 + 简单算法 | Python 编程基础、简单算法 | 算法进阶、机器学习与神经网络概念 |
| 激励称谓 | **星星**，且**不开放排行榜** | 星星 | 积分 + 段位（青铜→王者） | 积分 + 段位 |
| 编程题 | 不开放 | 开放（含"输出要求/示例"契约） | 开放 | 开放（难度更高） |

> 学段不是前端开关，而是贯穿**提示词矩阵、内容检索过滤、难度与题型、UI 裁剪、激励口径、榜单可见性**的一条主线（服务端也按学段兜底，例如小学段调排行榜接口直接返回不开放）。

### 4.2 知识库构建（分层知识图谱）

- 官方教材入库（分块 + 向量化）→ 教材检索工具按学段过滤；
- 课程/资源/知识点与教材内容互通（课程关联知识点、资源挂课时）；
- 学生个人知识库（知识页）与官方库分离：学生上传资料 → AI 整理成知识页 → 确认入库后参与检索；**个人 Wiki 是"会自己长大的"**（对话中即可创建/编辑/归档成页）。

### 4.3 自适应学习引擎（个性化学习路径）

**闭环**：学情档案 → 生成学习路径（主线 + 兴趣分支，AI 产出叙事层：目标、阶段、节点任务）→ 进入节点学习（课程/教材/AI 讲解）→ **节点快测**（异步出题、服务端判分）→ 掌握度更新 → 未掌握自动回炉 / 已掌握解锁下一节点 → 到期复习（遗忘曲线）。

- **掌握度模型**：状态（未解锁/进行中/已掌握）+ 分数 + 练习次数 + 正确率 + 下次复习时间；
- **AI 与学生档案联动**（7.60）：从节点点「让 AI 讲讲/复盘/带我一轮复习」→ 提问里自动带上该节点的真实状态（掌握度、练习次数、下次复习、任务）→ **一键直达自动发送**；AI 也能主动查（`queryLearningPath` / `queryPathNode` / `planNextStep`）列出"到期待复习 → 进行中 → 薄弱点"的真实清单；
- **管理端可见**：学习分析、用户个人学习情况抽屉（含成长信息与最近流水）；
- **节点奖励**：节点完成 +15、整条路径完成 +50 并解锁「路径通学者」徽章。

### 4.4 游戏化教学设计（二期支柱 A，已上线）

| 模块 | 设计 | 学生端可见 |
|---|---|---|
| 积分账户与流水 | 唯一业务键（user+bizType+bizId）数据库级幂等；累计积分只增不减，可用积分可增可减 | 成长中心「明细」滚动列表 |
| 获取途径 | 每日签到（含连续天数阶梯 3/7/15/30）、课时测验、节点快测、编程通关、绘本创作、知识页入库、掌握知识点、连击（3/5/10 连对）、徽章奖励、路径奖励 | 流水里每条都写清原因 |
| 等级与段位 | 阶梯可配置（默认 1-10 级：0/100/300/…/4500），初高段显示段位名 | 成长环 + "还差 N 分升级" |
| 每日上限 | 只约束可重复来源（默认 200/天），防刷分 | 今日进度条 |
| 徽章 | 13 枚（首次通关、坚持 3/7/15/30 天、十全十美连对、知识点收割者、积分达人、编程新星/达人、小小创作者、知识整理家、路径通学者） | 徽章墙（未解锁压暗 + 进度） |
| 排行榜 | 本学段榜单（累计/本周）、昵称脱敏（首字+`***`+学号后四位）、**小学段不开放** | 排行榜标签页 |
| 兑换 | 用**可用积分**换两类权益：上传额度扩容（可多次）、朗读音色解锁；只扣可用积分，等级与累计不变 | 「兑换」标签页 |
| 管理端运营 | 积分规则参数（GAME 组）在线调整即生效、流水审计（含业务键）、人工补分（正数 + 必填原因） | 管理端「学习分析 → 积分运营」 |

**判分公平性**（与游戏化直接相关）：服务端权威判分，三种判定（关键词包含 / 输出精确匹配 / 正则）+
**输出契约**（题目可下发"输出要求 + 输出示例"，学生知道格式要求）+ 数值容差 + 换行与空白归一化 + 诊断提示；
编程比赛有独立排行榜与独立结算，**不产生全局积分**（避免比赛成绩冲击学习激励口径）。

## 5. 用户体验（15%）

| 方面 | 我们的做法 |
|---|---|
| 界面设计 | 暖色护眼主题（学生端）+ 管理端明暗双主题（含抽屉/表格暗色适配）；卡片化信息密度分级 |
| 交互流畅 | 流式首字即出（不等整段）；长列表**固定行数 + 内部滚动**（如积分明细 5 行、兑换记录 5 行），不把卡片顶高 |
| 稳定性 | 心跳 + 无限重连 + 断线补拉历史；消息级与路由级**双层错误边界**；积分/掌握度等非关键链路异常只记日志、不影响学习 |
| 异步体验 | 绘本/动画/路径/出题等长任务显示阶段与进度（如"正在录制旁白…"），可继续做别的事 |
| 低龄适配 | 小低学段裁剪导航与内容，字号与文案单独适配；排行榜按学段关闭 |
| 出错的体面 | 积分不足、音色未解锁、余额不足等都给"可操作的下一步"，而不是一句"失败" |

## 6. 创新性（15%）

### 6.1 会自己长大的个人 Wiki（知识页闭环）

学生上传资料或对话中产生的知识 → AI 用工具**创建/编辑/归档**成知识页 → 目录管理（新建文件夹、移动）→ 确认后入库参与检索。
即"学生的资料不是躺在硬盘里，而是变成可被 AI 检索、可被引用的个人教材"。

### 6.2 掌握度驱动的学习路径（不是静态课表）

路径由 AI 依据学情档案生成（主线 + 兴趣分支 + 叙事层任务），**状态由掌握度驱动**：未掌握自动回炉、已掌握解锁下一节点、到期进入复习；每一步都有真实数据支撑，AI 讲评时也引用同一份数据。

### 6.3 游戏化 ≠ 积分装饰

积分是**经济系统**：唯一写入者 + 数据库级幂等 + 每日上限 + 兑换消费 + 段位阶梯 + 徽章 + 连击 + 排行榜（且比赛与全局积分严格分离）；
每一条规则都可用管理端参数调整、每一笔都可审计（含业务键）。

### 6.4 学生个性化与用户端提示词规则（计划 C，设计已完成）

常驻学生画像（掌握度/路径/积分/偏好速览）注入 + 用户可编辑的**受约束提示词规则**（称呼、长短、风格、难度、示例偏好、禁止事项），
并与知识页打通：**《我的学习偏好》是一篇受保护的系统知识页**（置顶、不可移动、不做向量化、不可删除但可重置），
学生可以直接改、也可以在对话里让 AI 记（"以后叫我小明"→ AI 提议 → 学生确认 → 落成文档），
优先级严格为「平台安全 > 平台事实 > 学段模板 > 用户规则 > 会话临时」，并对越权提示词做拦截与审计。

### 6.5 新手引导（计划 D，设计已完成）

首次登录欢迎卡 → 按学段的分步高亮导览（小低 3 步 / 小高 5 步 / 初高 6 步）→ 空状态场景引导；
**右上角常驻「新手指引」入口**，忘记操作可随时重看，平台改版后还有"导览有更新"提示。

## 11. 答辩预判问题与答法（提前准备）

| 评委会问 | 我们的答法（可直接照答） |
|---|---|
| AI 会不会编造课程/数据？ | 平台事实只允许来自工具返回；提示词里有事实规则与"学习数据来源规则"；实测问"这个年级有哪些书"返回教材全量清单 |
| 个性化会不会被学生"玩坏"（提示词注入）？ | 用户规则只覆盖风格与偏好，优先级低于安全与事实规则；越权表述直接拒绝并记审计；服务端校验，不靠前端 |
| 判分会不会被钻空子？ | 判分在服务端、预期输出不下发前端；输出契约让学生知道格式要求；数值容差与归一化保证"相对公平"；比赛与全局积分分离 |
| 积分会不会变成刷分游戏？ | 唯一业务键幂等 + 每日上限只约束可重复来源 + 兑换需要消费 + 全部可审计 |
| 为什么排行榜用 SQL 不用 Redis ZSET？ | 学生量级小，SQL 足够；避免"账户与缓存双写不一致"这类平时看不出、活动当天才炸的问题 |
| 断网/超时会怎样？ | 心跳与无限重连、断线后自动补拉历史；流式 `done` 带全文；非关键链路（积分/掌握度）异常不影响学习 |
