## 2. 开发节奏与验收原则

1. **管理端 ↔ 用户端交替推进**：每个阶段都是一个“能演示的闭环”（管理端建数据 → 用户端消费数据 → 落库正确），做完即验收。
2. **验收以真实联调为准**：页面操作真实走后端接口 + 数据库，不用 mock；后期再做系统性验收（产品说明书逐项过）。
3. **走一步看一步**：当前只定稿 P0 + P1；P2–P7 仅列路线图，到阶段前再细化。
4. **参照**：`参考项目/easymall`（手敲严谨版）作为代码风格与 AI 链路的参照，只读。
5. **AI 相关配置外部化**：Key 一律走环境变量，禁止硬编码。

## 5. P1 · 账号体系闭环（1–2 天）

### 5.1 目标
管理端能维护学生账号，用户端按 Codex 模式实现免登录浏览 + 登录/注册弹窗，受保护页面自动要求登录。

### 5.2 管理端：用户管理接口（后端）

从旧版控制器（66402e8）恢复适配到新 common Service，前端页面已就绪。

| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/userInfo/loadDataList` | GET | 分页查询（email/stage/status/roleType 筛选） |
| `/api/userInfo/getInfo` | GET | 详情 |
| `/api/userInfo/add` | POST | 新增（密码 MD5，默认值：status=1、createTime） |
| `/api/userInfo/update` | PUT | 修改（password 为空不更新） |
| `/api/userInfo/del` | DELETE | 删除 |
| `/api/userInfo/changeStatus` | PUT | 启用/禁用 |

验收：管理端「用户管理」页新增学生 → 列表可见 → 编辑/启禁用/删除全部真实落库。

### 5.3 用户端：登录注册（Codex 模式）

**交互需求（已确认）**
1. **公开浏览**：不登录可打开 AI 助手、编程等公开页面。
2. **左下角固定登录入口**：
   - 未登录：显示「登录」按钮，点击弹出登录弹窗；
   - 已登录：显示头像/昵称，点击展开下拉菜单（个人中心、退出登录）。
3. **登录弹窗**：账号密码输入框 + 登录按钮；底部「没有账号？去注册」切换注册表单。
4. **注册表单**：用户名、邮箱、密码、确认密码；底部「已有账号？去登录」切回。
5. **受保护页面/接口**：未登录访问时自动弹出登录弹窗；登录成功后自动跳转到原本想访问的页面。
6. **AOP 拦截**：后端对需登录接口统一拦截（未登录返回 code=401）；前端对受保护页面做路由守卫，收到 401 自动弹登录弹窗。

**页面访问策略（初定，P1 实现时可微调）**

| 页面 | 是否需登录 |
|---|---|
| AI 助手（ai-tutor） | 可公开浏览；发消息时若未登录 → 弹登录弹窗（对话需关联学段） |
| 编程环境（coding） | 可公开浏览（Pyodide 纯前端运行） |
| 个性化学习路径（learning-path） | 需登录 |
| 课程教材（course-material） | 需登录 |
| 我的（profile） | 需登录 |

**后端任务**

| # | 任务 | 说明 |
|---|---|---|
| P1-1 | 学生端登录拦截器 | HandlerInterceptor 校验 `studentToken`（Redis），未登录返回 401；放行公开接口 |
| P1-2 | `StudentAccountController` | `/studentInfo/login`、`/logout`、`/getUserInfo`、`/register` |
| P1-3 | 注册逻辑 | 用户名 + 邮箱 + 密码（MD5），校验邮箱唯一；**学段补全方案见 5.5 决策点** |
| P1-4 | 登录返回结构 | `{token, userInfo}`（对齐前端 auth.ts） |

**前端任务**

| # | 任务 | 说明 |
|---|---|---|
| P1-5 | 移除强制 AutoLogin | 改为公开路由 + 受保护路由守卫（未登录 → 弹窗） |
| P1-6 | 左下角登录入口组件 | 未登录「登录」按钮 / 已登录头像昵称下拉（个人中心、退出登录） |
| P1-7 | 登录/注册弹窗组件 | 登录 ⇄ 注册切换，注册成功自动登录；记录 redirect 并回跳 |
| P1-8 | api/auth.ts 补 register | `POST /studentInfo/register` |
| P1-9 | 401 全局处理 | 请求拦截器收到 code=401 → 弹登录弹窗（不强制跳转） |

**验收（联调）**
1. 未登录打开 ai-tutor / coding 可正常浏览；
2. 未登录点「学习路径」→ 自动弹登录弹窗 → 登录后进入学习路径页；
3. 左下角「登录」→ 弹窗登录成功 → 变为头像/昵称 → 下拉含「个人中心、退出登录」；
4. 注册新账号（用户名/邮箱/密码/确认密码）→ 成功并自动登录；
5. 管理端「用户管理」页能看到新注册学生；
6. 退出登录 → 回到未登录态，再访问受保护页重新弹窗。

### 5.4 P1 依赖与约束
- 依赖 P0-4 环境可用（Redis 用于 token）。
- 密码统一 MD5 存储；邮箱为登录核心字段。
- 前端字段与后端驼峰一致，禁止别名。

### 5.5 P1 决策点（待定，不影响开工）
- **注册后学段补全**：注册表单不含学段（按需求），但系统要求学生必须有学段。
  - 方案 A：注册成功后在弹窗内追加一步「选择学段」；
  - 方案 B：注册默认 `PRIMARY_LOW`，在「我的」页面可修改学段。
  - 建议：P1-3 实现时默认方案 B（改动最小），并在「我的」页面提供学段编辑；如你希望方案 A 再调整。
