## 4. 接下来计划建议

按"补齐赛题硬指标优先"排序（与 `开发流程.md` 的推荐顺序基本一致，但把学生端练习提前）：

1. 学生端习题练习（最高优先）：按年级抽题 + 答题 + 客观题判分 + 错题/掌握度记录，打通 `practice_record / knowledge_mastery`，补齐"游戏化练习 + 自动批改反馈"，同时喂数据给学习路径。
2. 试卷管理学生端作答：复用习题链路，练习卷可抽题作答与判分。
3. 动画讲解（M4 最小闭环）：AI 生成 HTML/SVG -> 存资源中心 -> 独立播放页；这是成本低、演示效果好的第二/第三多模态加分点。
4. 绘本生成（M4）：面向小学低，主题 -> AI 文案 + `NEXORA_IMAGE_API_KEY` 配图 -> 翻页阅读。
5. 学习路径（M5 简化版）：基于学习行为 + 练习掌握度派生推荐路径，做轻量展示；主动引导做一个"课程/知识点推荐"关闭闭环。
6. 编程环境（M5，可最后）：Pyodide 预置代码框架跑通基础运行，最低成本补第 6 种多模态。
7. 收尾：项目报告（架构/大模型策略/多模态路线/知识库构建/难题）+ 部署说明整理。

### 协作注意
- 按 `docs/开发协作流程.md` 走分支：从 `main` 拉 `feature/*`，PR 合入，禁止直推 main；提交信息 `feat:/fix:/docs:`。
- 两人并行时建议按"页面域"切分（后端 + 对应前端同一个人），减少 Mapper/PO 冲突。
- 新 SQL 迁移用独立脚本放 `nexora-java/sql/`（与文档口径一致，当前缺目录），不改 `nexora_schema2.0.sql`。
- 长期任务与文档更新后，按 `开发流程.md` 维护规则同步「功能归档表 + 任务队列」并提交。

## 6. 团队决策讨论记录：游戏化练习

- 2026-08-21：团队倾向不开发"游戏化/趣味"层（徽章/积分/排行榜等），理由是赛题仅需 6 选 3、目前已选 5 种，游戏化被认为最难融入系统。
- 代码事实核对：`practice_record / knowledge_mastery` 的 PO、Mapper（含 insert/insertOrUpdate）、Service 均已存在，但 admin/web 当前没有任何写入方（只在学习分析里被读取）；agent 意图路由已包含 `QUIZ`。
- 决策待定：用户先在 IDEA/VSCode 实跑后再定。倾向结论：砍掉"趣味/游戏化"层可行，但建议保留最小"AI 出题 -> 客观题自动判分 -> 掌握度/练习记录"闭环，作为个性化学习路径（赛题评分项 3，占 20%）与学习分析练习统计的数据来源。
