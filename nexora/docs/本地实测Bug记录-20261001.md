## Bug 清单

### Bug-1（中，已修复）动画讲解生成失败：动画脚本 JSON 解析过严
- 现象：高一账号在 AI 助教发「生成一个冒泡排序的动画讲解」，约 10s 后后端抛 `RuntimeException: 动画脚本解析失败`（`AnimationScriptComponent.parseAndSanitize:101`），聊天里显示「AI 生成失败：AI 调用失败」。重试一次成功，说明是概率性触发（模型输出不稳定时必挂）。
- 根因：`parseAndSanitize` 要求整段模型输出去掉 ```json 围栏后必须是**纯 JSON**；当前对话供应商 glm-5.3-flash（强制思考型）输出常夹带前置说明/思考残留，整串解析即失败。DeepSeek 时期基本满足格式，所以旧链路没暴露。
- 修复（2026-10-01，已编译通过）：`parseAndSanitize` 解析失败时改为「提取首个括号平衡的 `{...}` JSON 子串再解析」（新增 `extractJsonObject`，跳过字符串字面量内引号与转义），仍失败才抛错，且把模型原始输出前 500 字符写进 WARN 日志便于排障。**生效需重启 nexora-web**（未重启，绘本异步任务在跑，重启会杀任务）。

### Bug-2（环境，中）opencode.ai 网关偶发 ConnectException
- 现象：21:39 连续 4 条 `MessageAggregator - Aggregation Error`，根因 `ConnectException`（连 `https://opencode.ai/zen/go/v1/chat/completions` 建连失败），该轮回复无法推送，前端一直「正在思考...」。
- 判断：与 `docs/联调验收.md` 排障表的 IPv6 黑洞/网络抖动一致，属本机网络环境问题而非代码缺陷；重试即可恢复。**录屏前建议**：IDEA 的 nexora-web 运行配置 VM options 加 `-Djava.net.preferIPv4Stack=true`（重启后生效），可同时缓解 Bug-3。

### Bug-3（环境，低）绘本插图图片下载超时
- 现象：《小铁的心愿》7 页插图生成期间多次 `绘本插图下载异常: HTTP connect timed out`（图片生成成功、但从图片 URL 下载落盘时超时），部分页自动补画也失败，最终 7 页成书但个别页显示「本页暂无插图」+「补画本页插图」按钮。
- 判断：与 Bug-2 同源（本机到外网图片 CDN 的连接问题）。系统侧表现符合设计：重试 3 次 → 自动补画 → 阅读页缺图兜底 + 手动补画入口，全程无崩溃。
- 建议：录屏前应用 Bug-2 的 IPv4 参数；成书后逐页翻一遍，对缺图页点「补画本页插图」补齐再录。

### Bug-4（中，已修复待验收）对话内出题/绘本不读会话上下文，指代型需求产物跑题
- 现象：学生先让 AI 讲解某知识点，再点「出题练习」（"针对刚才讲解的内容出几道练习题考考我"），出的《人工智能小测验》全是通用 AI 常识题，与刚才讲解无关（用户截图 2026-10-02）。同理"把刚才讲的内容做成绘本"会把整句原话当主题提交任务。
- 根因：`AgentChatComponent.handleQuizAnswer` 只把当前这句话传给 `QuizGenerateComponent.generate(stage, topic)`（出题组件发起的是无历史的新调用，system prompt 兜底"围绕人工智能通识课"→ 模型只能编通用题）；`handlePictureBookAnswer` 把用户原话 `.trim()` 直接当绘本主题。动画链路虽有 `resolveAnimationConcept` 指代解析，但取材的 `buildRecentTranscript` 不排除产物型消息——上轮刚出过题时文本稿里是"我出好了《XX小测验》…"，概念解析照样可能跑偏。
- 修复（2026-10-02，编译通过，**需重启 nexora-web 生效**）：① `buildRecentTranscript` 排除产物型消息（QUIZ/PICTURE_BOOK/ANIMATION 卡片短句）+ 支持最近一条 AI 讲解独立截断额度；② 出题走"指代词门控 → 3000 字符摘录 → `QuizGenerateComponent` 新重载 + 提示词硬规则（必须围绕摘录主题、禁止跑题）"；③ 绘本同门控 → 新增 `PictureBookGenerateComponent.resolveTopic` 解析具体主题再提交任务。方案详见 `docs/AI助教出题上下文修复-设计方案.md`（含 6 条验收清单）。
- 状态：已编译，待用户重启 nexora-web 后按方案第 6 节清单本地验收。

## 复测（2026-10-02，nexora-web 14:38 重启后）

- **Bug-1 已修复并复测通过**：AI 助教发「生成一个冒泡排序的动画讲解」**一次成功**（14:54 日志「动画产物已存入个人知识库」，全程零 WARN/ERROR），生成《冒泡排序：把最大的数一步步冒到右边》8 步，聊天内播放器/全屏页正常。
- **Bug-2 间歇复现，确诊为 DNS/边缘节点问题**：15:10-15:12 连续两轮对话报 `SSLHandshakeException: Remote host terminated the handshake`。实测本机对 `opencode.ai` 的解析结果：IPv6（2406:cb42::/…）与部分 IPv4 边缘节点返回的 TLS 证书**域名不匹配**（被劫持/黑洞），属本机网络环境问题，与代码无关；15:19 起自行恢复（节点快测出题成功）。缓解手段不变：运行配置加 `-Djava.net.preferIPv4Stack=true` + 失败重发。
- **重要发现：网关抖动期间 RAG 层完全不受影响**——即使 LLM 调用失败、回复显示「AI 生成失败」，失败消息下方照样挂出了**个人知识页引用链接卡**（检索、引用组装发生在模型调用之前），录屏演示时若遇网络抖动，可先讲检索层再重试。
