# Nexora 项目报告

> 赛题:JBGS-2026-02 多模态K12人工智能通识课教学助手对话智能体
> 版本:2026-08-22 初稿(随功能增量同步更新)
> 系统:Nexora(Nexus 连接 + Aurora 极光)——K12 人工智能通识课教学助手

---

## 1. 系统架构设计

### 1.1 总体形态

前后端分离,服务端拆分为三个独立后端 + 一个公共模块,两个前端工程:

```text
nexora/
  nexora-java/
    nexora-common   公共层:PO / Service / Mapper / 枚举 / DTO / VO / Redis 组件 / AI 公共组件 / 异常 / 工具
    nexora-admin    管理端服务(6061):账号 / 资源中心 / 官方知识库 / 课程 / 习题 / 试卷 / 学习分析 / 系统设置
    nexora-web      学生端服务(6060 / WebSocket 6062):账号 / 资源中心 / AI 对话(Netty WS 流式) / 动画 / 绘本 / 编程 / 知识页
    nexora-mcp      MCP 教学工具服务(8084,Streamable HTTP,白名单工具,骨架待填充)
  nexora-front/
    nexora-front-admin   管理后台(3001,React 19 + antd v6)
    nexora-front-web     学生端(3000,React 19 + antd v6,极光主题)
```

依赖方向:`admin → common`、`web → common`、`mcp → common`,common 不反向依赖任何端。

### 1.2 关键中间件

| 中间件 | 用途 |
|---|---|
| MySQL 8 | 业务数据(用户/资源/知识文档/课程/题库/会话消息/生成记录/学习档案等) |
| Redis | 登录态、异步任务队列(资源上传 / 知识导入)、上传分片会话、消息取消标记、提示词覆盖 |
| Elasticsearch | 向量库(nindex `nexora-index-vectorstore`,1024 维)+ 向量检索 |
| Netty(内嵌 6062) | AI 回复流式推送:HTTP 发送消息返回 messageId,Netty WebSocket 按 userId 增量推送 |
| ffmpeg / ffprobe | 视频转码 HLS + 封面 + 时长探测 |

### 1.3 学生端核心链路(已跑通)

```text
资源上传 → 分片上传(Redis 会话)→ 队列合并落盘
  ├─ 文档:个人库 two-stage ——「生成 Wiki」AI 整理草稿 → 用户编辑 → 确认 → 向量化(RAG 可检索)
  ├─ 图片/视频:「标题 + 简介」轻量知识页草稿 → 用户确认 → 向量化(可检索并跳预览)
  └─ AI 对话:意图路由 → (理科求解/动画/出题/绘本生成等直接模型;讲解/概念走 RAG 检索)
       → 流式回复(WS)+ 推荐卡片 / 动画卡片 / 答题卡片 / 动作卡片
```

## 2. 大模型调用策略

### 2.1 模型分工

| 职责 | 模型 | 接入 |
|---|---|---|
| 对话 / 意图分析 / 动画脚本 / 出题 / AI 结构化整理 / 绘本故事 | DeepSeek(OpenAI 兼容协议,`NEXORA_DEEPSEEK_API_KEY`) | Spring AI ChatClient,统一封装在各 Component |
| 知识向量化 embedding | 阿里百炼 qwen3.7-text-embedding(1024 维,`NEXORA_DASHSCOPE_API_KEY`) | Spring AI ES VectorStore |
| 绘本插图文生图 | 阿里百炼 qwen-image-3.0(`NEXORA_IMAGE_API_KEY`,prompt_extend) | 自研 HTTP 调用(同步结果 + 异步任务轮询) |

设计目标:单一模型供应商固定成本低;后续切换更强教育模型(如 Gemini)只改配置与组件内部实现,业务层不变。

### 2.2 调用策略

- **统一封装**:所有模型调用收敛在组件层(IntentAnalyzerComponent / AgentChatComponent / AiStructureComponent / QuizGenerateComponent / AnimationScriptComponent / PictureBookGenerateComponent),Controller 禁止直接调 ChatClient / VectorStore。
- **意图路由先行**:每次提问先 LLM 意图分类(10+ 意图),再决定链路;理科求解类先用关键词规则命中(省一次模型调用)。
- **检索降本**:生成类意图(动画/出题/绘本/理科求解)跳过 RAG 检索(省 embedding + ES 查询);讲解概念类才检索。
- **流式输出**:对话回复必须流式经 Netty WS 下发,支持取消(Redis 取消标记),禁止同步阻塞。
- **分级兜底**:一切产物生成失败自动降级——动画/出题降级为文字讲解,绘本单页插图失败降级纯文字页,意图解析失败兜底 CHAT。

## 3. 多模态生成技术路线(6 种已落地)

赛题要求 ≥3 种,本系统落地 6 种:

| 模态 | 实现 | 产物与展示 |
|---|---|---|
| ① 对话问答 | 意图路由 + RAG + 流式 WS | 聊天气泡 + Markdown 渲染(代码高亮) |
| ② 多模态教学(资料推荐) | RAG 命中 → 推荐卡片 | 视频/图片/文档/链接卡片跳预览 |
| ③ 动画讲解 | LLM 生成分步 SVG 脚本 JSON → **白名单清洗** → 播放器 | 对话内动画卡片(步骤导航 + SVG 画面 + 讲解文字)+ 动画独立页列表/全屏播放 |
| ④ 绘本生成 | LLM 故事分页 + qwen-image 逐页文生图 → 下载本地 | 绘本页(主题生成 + 列表)+ 图文翻页阅读器 |
| ⑤ 编程环境 | Monaco 编辑器 + Pyodide 浏览器内运行 Python | 学段预置框架(小高/初中/高中)、运行输出、保存学习沉淀知识库 |
| ⑥ 游戏化练习(答题卡片) | LLM 出选择测验 JSON → 前端即时判分 | 对话内答题卡片(作答/判分/解析/得分/重练) |
| 附 学习沉淀 | 对话/课程一键「同步知识页」 | 知识页草稿 → 两段式确认 → 入向量库 |

安全措施:LLM 生成的 SVG 经后端白名单清洗(仅保留基础图形标签,剔除 script/style/事件属性/href/javascript 引用,超长丢弃),前端渲染前 DOMParser 二次剥离;绘本文生图仅接受 dashscope 返回 URL 并下载到本地;答题/动画 JSON 均有结构校验,解析失败降级。

## 4. 知识库构建方法

### 4.1 两段式「确认后入库」原则

无论是官方库还是个人库,进入向量库的内容必须经过「AI 结构化整理 + 人工确认」:

```text
官方库:上传资源 → 提取文本 → AI 整理结构化 MD(管理端「AI 文档整理」页,可编辑)→ 管理员确认 → 向量化
个人库:上传仅存原始(raw)→「生成 Wiki」→ AI 整理草稿(可编辑)→ 用户确认 → 向量化
对话/课程同步:提问/课程资源 → AI 整理 → 知识页草稿 → 用户确认 → 向量化
```

### 4.2 检索设计

- 向量存储:ES,metadata 固定 `docId / title / dataType / stage / knowledgePointId / difficulty / ownerId / sourceResourceId / sourceUrl`。
- 检索顺序:个人库(ownerId 过滤,**仅已确认页** vectorStatus=2)→ 官方知识库(ownerId 为空)→ 空命中时明确告知「知识库中暂无相关内容」,不编造。
- 策略:向量优先(topK 10-15,相似度阈值 0.5)→ 关键词回退(MySQL LIKE + 分块命中计数);推荐卡片携带 resourceId/type 跳资源预览。
- 检索隔离:个人知识按 ownerId 彻底隔离;管理端资源与个人资源互不可见。

### 4.3 理科意图分流

「帮我解一元二次方程」「并联电阻怎么算」等理科求解直接走模型(不检索本地库);概念类问句(什么是/解释/为什么 开头)豁免关键词规则,仍走 RAG 优先。双保险:关键词规则(省调用)+ LLM 意图分类。

## 5. 年级自适应机制

- 学段四档:PRIMARY_LOW / PRIMARY_HIGH / JUNIOR / SENIOR,冗余在 user_info.stage,年级在 grade。
- 自适应点:AI 提示词(每个意图的提示词按学段替换 `{stageDesc}`)、RAG 检索(metadata stage 过滤)、UI(小低大按钮/绘本、初高中编程与动画、编程预置框架按学段)、题库(按年级抽题)。
- 交互映射:小低 → 绘本+游戏;小高 → 图形化循环;初中 → 列表/turtle;高中 → 算法/递归。

## 6. 个性化学习路径基础

- 个人知识库三层(raw 原始资料 / wiki 知识页 / attachments 附件)+ 300MB 额度,上传自动归类。
- 学习档案(user_wiki_profile):学习目标 / 关键问题 / 兴趣学科 / 术语叫法,AI 沟通与推荐据此适配(后续接入提示词)。
- 学习行为沉淀:对话「同步知识页」、课程「生成知识页草稿」、编程「保存学习」均沉淀为可确认的知识页;删除资源级联清理知识页与向量。
- 学习分析(管理端):课程进度 / 练习 / 知识库 / AI 对话与 Token / 掌握度六类统计(聚合一表查询,无循环查库)。

## 7. 工程难题与解决方案

| 难题 | 方案 |
|---|---|
| PDF 公式/文本自动解析质量差 | 放弃 PDF 自动解析(7.18):管理员 PDF 转 Word → docx 解析(段落+表格)→ 左写右 KaTeX 预览 → 结构化入库;数学计算交给大模型 |
| LLM 生成 SVG 的安全与质量 | 后端白名单清洗(标签/属性/长度三重过滤)+ 前端 DOMParser 二次剥离;分步讲解容错(无图步骤纯文字) |
| 个人库内容质量不可控 | 两段式确认:上传只存原始,AI 整理后必须用户确认才向量化;检索只查已确认;编辑/重新生成自动清理旧向量 |
| 图片/视频无法提取文本 | 以「标题 + 简介」轻量向量化(确认时自动刷新最新简介,手动编辑内容不覆盖) |
| 理科提问被知识库误导 | 关键词规则 + LLM 双判定的 SCIENCE_SOLVE 分流,概念类前缀豁免 |
| 超长文档整理截断 | AiStructureComponent 按 6000 字符分段(换行切分)逐段 AI 整理后拼接 |
| 视频处理慢 | 上传异步:分片 → Redis 队列 → 合并 → ffmpeg 转 HLS(任务状态可见) |
| 浏览器运行 Python | Pyodide(CDN 发行版)+ Monaco;预置框架按学段;输出采集支持交互输入 |
| 模型调用成本与延迟 | 意图先行省调用;生成类跳过 RAG;关键词规则直出;低配流式体验 |
| 演示环境断网风险 | 动画/出题/整理/绘本故事均有降级;绘本插图失败降级纯文字;编辑器/Pyodide 需联网(CDN) |
| 迁移脚本与存量数据 | 系统目录 dir_type 幂等补齐(存量账号自动获得三层);不修改既有 DDL,新增迁移脚本 |

## 8. 部署与集成方案

### 8.1 环境依赖

MySQL 8(nexora 库)、Redis 6379、Elasticsearch 9200(索引自动初始化 `initialize-schema=true`)、ffmpeg/ffprobe(视频转码)、Node 22+、JDK 21。

### 8.2 环境变量(API Key 一律外部化)

| 变量 | 用途 |
|---|---|
| `NEXORA_DEEPSEEK_API_KEY` | 对话/意图/动画/出题/整理/故事 |
| `NEXORA_DASHSCOPE_API_KEY` | embedding(qwen3.7-text-embedding) |
| `NEXORA_IMAGE_API_KEY`(默认回落 DASHSCOPE) | 绘本文生图(qwen-image-3.0) |
| `NEXORA_MCP_CLIENT_ENABLED` | 学生端 MCP 客户端开关(默认 false) |

### 8.3 服务与端口

| 服务 | 端口 | 说明 |
|---|---|---|
| nexora-web | 6060 / WS 6062 | 学生端后端 + Netty WebSocket |
| nexora-admin | 6061 | 管理端后端 |
| nexora-mcp | 8084 | MCP 教学工具(Streamable HTTP,可选) |
| 学生端前端 | 3000 | 代理 /api → 6060、/ws → 6062 |
| 管理端前端 | 3001 | 代理 /api → 6061 |

### 8.4 运行步骤

1. 启动 MySQL / Redis / ES;执行 SQL(`docs/nexora_schema2.0.sql` 初始化 + 迁移脚本 `nexora-java/sql/20260822_student_wiki.sql`);
2. 配置上述环境变量;
3. 分别启动四个后端服务(或去掉 mcp);
4. 启动两个前端(Vite dev 或 build 后静态托管,注意 /api 与 /ws 代理);
5. 管理端登录 → 上传资源 → AI 文档整理 → 确认入库;学生端注册(默认小学低年级,可改学段)→ 三层资源中心 / AI 助教 / 动画 / 绘本 / 编程。

### 8.5 集成方式

独立 Web 应用(前后端分离 + 标准 HTTP/WebSocket API),可通过页面嵌入(iframe)或对接 `/api` 接口接入第三方平台;媒体接口(视频 HLS / 图片 / 文档 / 页面)按直连公开设计。
