## 1. 项目定位

Nexora 是 K12 人工智能通识课教学助手（赛题 JBGS-2026-02），产品名含义为 Nexus 连接 + Aurora 极光。

- 管理端：维护学生、用户、资源、后续知识库、提示词等内容。
- 学生端：AI 助教、绘本、课程教材、个性化学习路径、编程环境等学习场景。
- 后端：Spring Boot 3 多模块工程，管理端 / 学生端 / MCP 服务拆分。
- 核心角色：仅学生 + 管理员两类；AI 智能体承担“7×24 在线教师”职责。
- 学段：小学低 / 小学高 / 初中 / 高中，UI 已改为按“年级”表达。

## 2. 已确认的产品与技术方向

### 2.1 开发方式

- 不再按固定排期推进，采用“功能块”方式：完成一块功能后再构思下一块。
- 每个功能块必须包含：目标、范围、验收口径；验收以真实前后端联调为准。
- 后续 AI 会话先读本文件，再结合 git 历史判断当前断点。

### 2.2 RAG 技术结论（WaLiAPI 审查后确认）

参考项目 `WaLiAPI-Java` 的 RAG / Wiki 已完整审查，结论如下：

**M2 RAG 按以下结构落地：**
- 导入流水线任务化：知识库 → 文档 → 分块 → 向量化 → 任务进度 → 检索测试。
- 分块：Markdown 按标题优先分块，超长再按自然边界二次切分，单块 ≤ 500 字。
- 向量存储：使用 ES，不复制 WaLiAPI 的 MySQL BLOB + 自研 HNSW。
- 向量模型：阿里百炼 `text-embedding-v4`（1024 维），metadata 固定为 `dataType / stage / knowledgePointId / difficulty`。
- 检索：hybrid 模式，向量 + 关键词，失败自动回退；topK 10~15，相似度阈值 0.5。
- 无命中：提示词明确告知“知识库中暂无相关内容”，模型不得编造。
- 管理端提供导入状态、任务进度、检索测试与召回块展示。

**Wiki 只借鉴图谱增强 RAG 概念，放到个人知识库后期：**
- 页面带结构化元数据（标题、标签、知识点、年级）。
- 页面间使用 `[[wikilink]]`、标签等关系建边。
- 回答时先检索页面，再沿图谱扩展 1-hop 关联页面，增强上下文。

**不整套引入：**
- 不引入 MySQL 存向量、自研 HNSW、Google ADK 全套 Agent 装配。
- 不引入多供应商网关、渠道调度、API Key 计费体系。
- 安全扫描按需裁剪，只保留提示词注入、工具风险、密钥泄露等必要检查。

### 2.3 学生端个人 AI 知识库（亮点功能，方案 A 已确认）

产品定位：**学生的个人 AI 知识库 / 第二大脑**，放在学生端，由学生自己维护。

已确认采用**服务端个人私有空间**：数据存服务端，仅对本人可见，AI 可检索，支持跨设备。

**与官方知识库的关系：**
- 官方知识库：管理员维护，面向全体学生，按学段 / 知识点 / 难度组织。
- 个人知识库：学生自己维护，只属于当前学生。
- AI 回答顺序：个人知识库 → 官方知识库 → 通用对话；引用时标注来源。

**个人知识库 MVP 功能块：**
- 学生端新增“我的知识库”入口，支持目录 / 页面 / 标签 / 搜索。
- 学生可创建、编辑 Markdown 页面，支持文件夹组织和 `[[wikilink]]`。
- 支持导入 Markdown / TXT 文件；Word / PPT / PDF 解析后续再补。
- 入库到 ES，metadata 增加 `ownerId` 与 `scope=PERSONAL`，保留 `stage / knowledgePointId / difficulty / tags`。
- AI 助教检索个人库时强制 `ownerId` 过滤，禁止跨用户读取。
- 管理端默认不读取个人库内容，只做必要的数据统计或安全治理（具体权限待定）。

**个人知识库后期增强：**
- “我的知识图谱”：把学生页面的 wikilink / 标签 / 知识点关系可视化为图谱。
- 图谱增强问答：检索到页面后沿边扩展关联页面，回答更连贯。
- 学习记录联动：个人库内容可与错题、笔记、学习路径打通。

**明确不做：**
- 不做浏览器本地离线存储方案。
- 不做多用户共享、评论协作、公共 Wiki 社区。
- 不复制 WaLiAPI 的完整 Wiki 项目 / 来源 / 任务表体系，按 Nexora 场景简化。

```text
nexora/
  nexora-java/
    nexora-common/   PO / Service / Mapper / 枚举 / DTO / VO
    nexora-admin/    管理端后端接口
    nexora-web/      学生端后端接口 + AI 对话 + Netty WebSocket
    nexora-mcp/      MCP 教学工具服务（启动类，工具待补）
  nexora-front/
    nexora-front-admin/  管理后台前端（React 19 + TS + antd v6）
    nexora-front-web/    学生端前端（React 19 + TS + antd v6）
  docs/              开发流程（唯一执行依据）、方案文档（开发排期仅历史参考）
knowledge/          RAG 知识库源文件（当前为空，M2 待补）
```

## 4. 技术栈与统一约定

- 后端：Spring Boot 3.x、Java 21、MySQL 8、Redis、Elasticsearch、Spring AI、Netty WebSocket。
- 前端：React 19、TypeScript、Vite、antd v6、Zustand、React Router。
- 接口风格：`/api/<模块名>/<动作>`，动作统一为 `loadDataList / getInfo / add / update / del / changeStatus`。
- 统一返回 `ResponseVO<T>`：`{ status, code, info, data }`。
- 严格分离 PO / DTO / VO，禁止返回裸 Map（历史遗留除外）。
- 大模型调用、向量检索、MCP 工具调用统一封装，禁止散落进 Controller。
- AI Key 全部走环境变量 / 外部配置，禁止硬编码。
- `参考项目/` 只读，已加入 `.gitignore`。

## 10. 功能块设计：M2 官方 RAG（待确认后开工）

### 10.1 目标

完成官方知识库闭环：管理端维护知识文档 → 解析分块 → ES 向量入库 → 学生端 AI 助教按学段检索回答 → 管理端检索测试。

### 10.2 范围

**本轮做：**
- 补齐 `knowledge/` 示例文档：每个学段 1~2 篇 Markdown，带 `stage / knowledgePointId / difficulty / title / dataType` frontmatter。
- 管理端「知识文档」页真实接口：列表、新增、编辑、删除、批量导入 `knowledge/`、向量入库、重新入库。
- 管理端「入库状态」页：展示 `vectorStatus / vectorError / chunkCount`，失败原因可查看。
- 管理端「检索测试」：输入问题，按学段 / 知识点 / 难度过滤，展示召回 chunk、相似度、来源文档。
- 学生端 AI 助教：提问时先检索官方知识库，命中内容注入提示词；无命中时明确回答“知识库中暂无相关内容”，不编造。

**知识库管理入口重设计（已确认，旧三个入口舍弃）：**

| 新入口 | 路径 | 说明 |
|---|---|---|
| 知识总览 | `/knowledge/overview` | 文档数、知识点数、已入库数、分块数、失败数、学段分布、入库状态分布 |
| 知识目录 | `/knowledge/catalog` | 学段 → 学科 → 知识点树 + 文档列表；知识点与文档在此统一维护 |
| 问答测试 | `/knowledge/test` | 输入问题，按学段 / 知识点 / 难度筛选，查看召回 chunk 与相似度 |

旧入口 `知识文档 / 知识点管理 / 入库状态` 删除，不再保留。

**本轮不做：**
- 不做 Word / PPT / PDF 解析（下一轮补 POI / PDFBox）。
- 不做视频 ASR 转写。
- 不做 MCP 知识库工具（M3 再做）。
- 不做个人知识库（M2 稳定后单独设计）。
- 不新增 MySQL 分块表；chunk 本体存 ES，MySQL 只保留文档级状态。

### 10.3 数据与状态

- 复用现有表：`knowledge_doc`、`knowledge_point`，不新增 DDL。
- `knowledge_doc.vectorStatus`：0 待处理 / 1 处理中 / 2 已完成 / 3 失败 / 4 过期。
- `vectorError` 保存失败原因；`chunkCount` 保存 ES 实际入库分块数。
- 批量导入 `knowledge/` 时逐篇处理，接口返回成功 / 失败统计，不引入独立任务表。
- ES 索引沿用 `nexora-index-vectorstore`，维度 1024，metadata 固定：
  - `docId`
  - `chunkIndex`
  - `dataType = KNOWLEDGE`
  - `stage`
  - `knowledgePointId`
  - `difficulty`

### 10.4 检索与 AI 接入

- 新增 `RagSearchComponent`：
  - 先走 ES 向量检索：按 `stage` 过滤，topK 10~15，相似度阈值 0.5。
  - 向量无结果或低于阈值时回退 MySQL 关键词检索（`content LIKE` + 标题匹配）。
  - 按 `docId` 去重，输出 `ragData`（来源标题 + 文档名 + 相关片段）。
- 接入 `AgentChatComponent`：
  - 意图分析后，除纯闲聊外都尝试检索官方知识库。
  - 检索结果通过 `{{ragData}}` 注入提示词；默认 Prompt 无该占位符时自动拼接“知识库参考内容”。
  - 回答要求标注来源；无结果时提示词明确禁止编造。

### 10.7 验收口径

1. 管理端导入 `knowledge/` 示例文档后，`knowledge_doc` 落库且 `vectorStatus=2`。
2. ES 中存在对应 chunk，metadata 含 `stage / knowledgePointId / difficulty`。
3. 检索测试输入“讲解冒泡排序”能召回对应学段 chunk，并展示相似度。
4. 学生端 AI 助教说“讲解冒泡排序”时回答引用知识库内容；无命中问题不编造。
5. 重复入库不产生重复 chunk；内容更新后重新入库能覆盖旧 chunk。

### 10.8 个人知识库预留

`RagSearchComponent` 检索参数预留 `scope` 与 `ownerId`：
- 官方库：`scope=OFFICIAL`，不传 `ownerId`。
- 个人库：`scope=PERSONAL`，强制传当前用户 `ownerId`。

## 11. 功能块设计：资源解析入库（待开工）

### 11.1 目标

打通资源管理与知识库：管理端选择已上传资源，解析抽取文本 → 清洗 → 分块 → 向量化入库，学生端 AI 可直接检索。

### 11.2 支持的文件类型与处理方式

| 类型 | 处理方式 | 注意点 |
|---|---|---|
| `.txt` / `.md` | 直接读取文本 → 分块 → 向量化 | 无解析风险 |
| `.docx` | Apache POI `XWPF` 提取段落与表格文本 | 支持较好 |
| `.doc` | Apache POI `HWPF` 尽力提取 | 老格式复杂排版可能丢失内容，检测到 `.doc` 必须用 `message.warning` 提示转成 `.docx` |
| `.ppt` / `.pptx` | Apache POI `XSLF` 遍历每页 Slide 提取文本框 | 嵌入图片、图表内文字无法提取；幻灯片备注可一并提取 |
| `.pdf` | PDFBox `PDFTextStripper` 提取文本 | 文字型 PDF 效果好；扫描型 PDF 提取不到文字 |
| 视频 / PPT / 超链接 | 用户主动填写资料 | 与知识库“新增文档”方式一致，走手动维护 |

### 11.3 PDF 扫描版判断

- 用 PDFBox 提取文本后，按页统计有效字符数。
- 若文本为空或极少（例如平均每页少于 20 个有效字符），自动标记为“疑似扫描版”。
- 使用 `message.warning` 提示用户“疑似扫描版 PDF，需要 OCR 处理后才能入库”，不阻断其他操作。
- 第一版不接入 OCR；后续再接 PaddleOCR 或独立 OCR 服务。

### 11.4 入库流程

```text
选择资源 → 检测类型 → 提取文本 / 用户手动填写
    → 清洗（去页眉页脚、多余空白） → 分块（复用 TextChunker）
    → 向量化写入 ES → 更新 knowledge_doc（sourceResourceId / vectorStatus / chunkCount）
```

幂等规则：
- 同一资源重复导入时，通过 `sourceResourceId` 找到已有文档并更新，不产生重复文档。
- 重新解析后先删除旧 ES chunk，再写入新 chunk。

### 11.5 提示规范（已确认）

- 所有解析提示统一使用 antd `message` 组件：成功用 `message.success`，警告用 `message.warning`，失败用 `message.error`。
- 不使用弹框（Modal）做解析提示。
- 资源选择器可以使用弹窗，但选择后的结果提示仍走 `message`。

### 11.6 补充建议

- 大文件解析建议异步执行，并新增 `parseStatus` 字段（0 待解析 / 1 解析中 / 2 成功 / 3 失败），避免阻塞管理端接口。
- `vectorStatus` 继续表示向量化状态，解析失败原因写入 `vectorError`。
- 文件类型判断不能只信扩展名，可先用文件头/字节特征识别真实格式；第一版以扩展名 + POI/PDFBox 为主。
- 课程资源、视频、PPT、超链接统一走“手动填写资料”，复用知识目录的“新增文档”表单，`sourceType` 可扩展为：0 手动维护 / 1 资料解析 / 2 手动填写资源说明。
- 验收口径：上传 `.txt / .md / .docx / .pptx / .pdf` 均可解析入库并在问答测试中召回；`.doc` 和扫描版 PDF 正确出现 `message.warning`，不产生脏数据。
