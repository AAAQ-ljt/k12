## 1. 项目定位

Nexora 是 K12 人工智能通识课教学助手（赛题 JBGS-2026-02），产品名含义为 Nexus 连接 + Aurora 极光。

- 管理端：维护学生、用户、资源、知识库、提示词等内容。
- 学生端：AI 助教、绘本、课程教材、个性化学习路径、编程环境等学习场景。
- 后端：Spring Boot 3 多模块，管理端 / 学生端 / MCP 服务拆分。
- 核心角色：仅学生 + 管理员两类；AI 智能体承担“7×24 在线教师”职责。
- 学段：小学低 / 小学高 / 初中 / 高中，UI 已按“年级”表达。

## 3. 技术栈与统一约定

- 后端：Spring Boot 3.x、Java 21、MySQL 8、Redis、Elasticsearch、Spring AI、Netty WebSocket。
- 前端：React 19、TypeScript、Vite、antd v6、Zustand、React Router。
- 接口：`/api/<模块名>/<动作>`，统一返回 `ResponseVO<T>`。
- 约定：PO / DTO / VO 分离；AI 调用统一封装；AI Key 走环境变量；`参考项目/` 只读并已忽略。

## 4. 已确认的产品与技术方向

### 4.1 RAG 技术结论

- 向量存储使用 ES，metadata 固定为 `dataType / stage / knowledgePointId / difficulty`。
- 检索：向量优先，关键词回退；topK 10~15，相似度阈值 0.5。
- 无命中时明确告知“知识库中暂无相关内容”，禁止编造。
- 不引入 MySQL BLOB 向量、自研 HNSW、Google ADK 全套、多供应商网关。

### 4.2 个人 AI 知识库

- 方案 A 已确认：服务端个人私有空间，数据仅对本人可见。
- 回答顺序：个人知识库 → 官方知识库 → 通用对话。
- 检索必须按 `ownerId` 隔离。
- Wiki 借鉴结论见 4.4：raw 原始资料不可变 + wiki 知识页由 AI 维护，图谱只做派生视图。

### 4.3 提示规范

- 所有解析/操作提示统一使用 antd `message`：成功、警告、失败分别用 `success / warning / error`。
- 提示不使用 Modal 弹框；资源选择器等选择场景可以使用弹窗。

### 4.4 优秀开源参考：llm-wiki-skill-main（2026-08-15）

参考项目位于 `参考项目/llm-wiki-skill-main`（Karpathy LLM Wiki 方法论的完整实现，含 Skill 形态 + agent 工作台），只读，不引入代码，只借鉴思路。

#### 4.4.1 核心模型

- 三层结构：`raw/` 原始素材（不可变事实来源）、`wiki/` 知识层（AI 维护、可复利）、schema 配置（规则与工作流）。
- 核心动作：`init / ingest / query / digest / lint / status / graph / delete / crystallize`。
- 页面类型：素材摘要、实体页、主题页、对比分析、综合分析、保存的查询结果；统一 frontmatter + `[[wikilink]]` 互链。
- 辅助资产：`index.md`（目录）、`log.md`（操作日志）、`purpose.md`（研究目标与关键问题）、`.wiki-cache.json`（SHA256 去重）、`.wiki-schema.md`（维护规则 + 别名词表）。

#### 4.4.2 可借鉴机制

- 消化分两步：先结构化分析（entities / topics / connections / confidence / evidence），再生成页面；格式校验失败自动回退单步，避免脏数据。
- 置信度四档：`EXTRACTED / INFERRED / AMBIGUOUS / UNVERIFIED`，AI 生成内容必须可回溯到原文或明确标注推断。
- SHA256 缓存：同一素材无变化直接复用已有结果；删除素材时级联清理引用、缓存与断链。
- 查询链路：先读索引 + 别名词表展开，再检索页面与命中段落，控制上下文上限，回答必须附引用；有价值的回答可沉淀为新页面。
- 批量消化：便宜模型做 digest 子代理，并发受限，子代理只输出 Markdown，主进程写盘；主对话仍用主模型。
- Lint：扫描孤立页、断链、矛盾、索引缺失和置信度报告，只给建议，确认后才修改。
- 图谱：是 wiki 页面关系的派生视图，不是事实来源；想改结构就改页面，再重新生成图谱。
- 工程取舍：本地优先，知识库 / 应用状态 / 模型凭证三类数据严格分离；不用 MCP（本地过重）；SSE 流式；Obsidian 兼容（纯 Markdown，AI 不碰第三方元数据）；会话绑定知识库防止跨库污染。

#### 4.4.3 Nexora 落地建议

- 不照搬本地文件系统与 Obsidian，映射到现有 MySQL + ES + 资源中心：
  - raw = `resource_info`（`owner_id` 非空，即学生个人资源）；
  - wiki 页面 = 新增 `wiki_page`（`owner_id / pageType / title / contentMd / frontmatter / sourceIds / confidence / status`），或先以 Markdown 文本存 `knowledge_doc`；
  - index/log = 页面统计 + 操作记录；purpose = 学生「我的学习目标 / 关键问题」配置；
  - 去重 = `knowledge_doc.sourceResourceId` + 文件 SHA256，重复导入跳过。
- 个人库检索顺序维持：个人知识库 → 官方知识库 → 课程资源；wiki 页结构化结果优先于原文 chunk，回答附页面引用。
- 消化任务复用现有 Redis 异步队列：提取文本 → 分块 → 向量化 + AI 生成摘要/实体/主题页 → 更新索引与日志；失败可重试。
- 删除资源时级联删除个人 wiki 页与 ES chunk；图谱/知识地图放到后期，只做轻量派生视图，不做独立工作台。
- 不引入：本地 Obsidian 依赖、MCP 服务、多模型角色、独立图谱引擎；当前单模型 + 现有异步队列足够。

### 4.5 题目公式与图片方向

- 数学公式使用 Markdown + LaTeX：行内 `$...$`、块级 `$$...$$`，后台编辑器与学生端统一用 KaTeX 渲染；数据库保存 LaTeX 原文。
- 含图题的图片统一引用资源中心 `resource_id`，写入 `question_info.question_image`（逗号分隔，支持一题多图）。
- AI 出题只生成不含图片的题目；含图题由 PDF 录入模式或管理员手动补图解决。

## 7. 当前功能块设计：资源解析入库

### 7.1 目标

打通资源管理与知识库：管理端选择已上传资源，解析抽取文本 → 清洗 → 分块 → 向量化入库，学生端 AI 可直接检索。

前置组件：`BaseDrawer`（已完成，提交 `1afa174`）用于资源选择、解析详情等抽屉场景。

### 7.2 文件类型与处理方式

| 类型 | 处理方式 | 注意点 |
|---|---|---|
| `.txt` / `.md` | 直接读取文本 → 分块 → 向量化 | 无解析风险 |
| `.docx` | Apache POI `XWPF` 提取段落与表格 | 支持较好 |
| `.doc` | Apache POI `HWPF` 尽力提取 | 老格式可能丢内容，用 `message.warning` 提示转成 `.docx` |
| `.ppt` / `.pptx` | Apache POI `XSLF` 遍历每页 Slide 提取文本框 | 图片/图表内文字无法提取；备注可一并提取 |
| `.pdf` | PDFBox `PDFTextStripper` 提取文本 | 扫描型 PDF 提取不到文字 |
| 视频 / PPT / 超链接 | 用户主动填写资料 | 复用知识目录“新增文档”方式 |

### 7.3 PDF 扫描版判断

- 按页统计有效字符数，文本为空或极少时标记为“疑似扫描版”。
- 使用 `message.warning` 提示需要 OCR 处理，不阻断其他操作。
- 第一版不接入 OCR；后续再接 PaddleOCR 或独立 OCR 服务。

### 7.4 入库流程与幂等

```text
选择资源 → 落库（处理中）→ Redis 异步队列 → 检测类型 → 提取文本 / 用户手动填写
    → 清洗 → 分块（复用 TextChunker） → 分批向量化写入 ES（每批 ≤15 条）
    → 更新 knowledge_doc（sourceResourceId / vectorStatus / chunkCount）
```

- 同一资源重复导入时，通过 `sourceResourceId` 更新已有文档，不产生重复。
- 重新解析先删除旧 ES chunk，再写入新 chunk。
- 大文件已异步解析：接口先返回任务状态，后台队列处理解析与向量化；`vectorStatus` 表示处理中/成功/失败。
- `sourceType` 扩展为：0 手动维护 / 1 资料解析 / 2 手动填写资源说明。
- 超链接文档走「文档录入」的 `sourceUrl` 字段，`dataType=LINK`，检索结果携带 `sourceUrl` 供学生端跳转。

## 7.7 当前功能块设计：习题管理重构（AI 出题 + PDF 录入）

### 7.7.1 目标

题库量必须支撑 AI 助教，放弃“管理员一条条手动录入”作为主路径，改为两种批量生产方式，共用同一套「题目 MD 规范 + 解析器」，最终结构化写入 `question_info / question_option`。

### 7.7.2 题目 MD 规范（公共底座）

- 一道题一个 Markdown 块，包含：年级、难度、题型、分值、题干、知识点、选项、解析。
- 公式使用 LaTeX：行内 `$...$`，块级 `$$...$$`；数据库保存 LaTeX 原文，后台编辑器与学生端均用 KaTeX 渲染。
- 图片引用：`![图1](@resourceId)`，一题可多图；解析时写入 `question_info.question_image`（逗号分隔 `resource_id`）。
- 图片统一存放 `resource_info`，复用资源中心上传、预览、下载能力。
- 解析结果先出“结构化草稿”，管理员确认后才批量入库，AI 不直接写库。

### 7.7.3 AI 出题模式

- 页面：习题管理 Tabs 中“AI 出题审核”改为“AI 出题”。
- Drawer（BaseDrawer）占屏约 80%：左侧配置，右侧 MD 编辑器（`@uiw/react-md-editor` + KaTeX 预览）。
- 左侧配置项：
  - 年级、知识点（按年级对应学段联动）；
  - 出题描述；
  - 知识库资料（可选）：选择资料后以资料内容为主出题；
  - 题量分配：按简单 / 中等 / 困难三档，由管理员直接为每档分配各题型数量，不单独设置总题数。
- AI 只生成不含图片的题目；如果某题必须配图，不生成该题或由管理员后续手动补充。
- 右侧可微调题干、选项、答案、解析、公式。
- 产出可：下载 `.md`、保存到资源中心（作为 DOCUMENT 资源）、直接解析入库。

### 7.7.4 PDF 录入模式（TODO，暂缓）

- 上传或从资源中心选择 PDF。
- 第一版处理链路：
  - PDFBox 抽取文本（公式可能乱序，不作为最终答案）；
  - PDFRenderer 将每页渲染为页图；
  - 右侧 MD 编辑器展示草稿文本 + 页图；
  - 管理员用 LaTeX 修正公式，从页图框选或整页插入题目图片；
  - 插入图片时上传到 `resource_info`，自动生成 `![图1](@resourceId)`。
- 第二版（P4-M4 多模态）再接入视觉模型把页图转 Markdown + LaTeX，第一版预留转换接口，不阻塞当前开发。
- 同一套 PDF → 草稿 MD → 结构化解析能力供后续试卷管理复用。

### 7.7.5 自动导入

- 两种入口：
  - 本地上传 MD 文件；

- 后端解析题目 MD → 返回结构化草稿 → 管理员确认 → 批量入库。
- 校验：字段完整性、知识点存在、题型 / 难度合法、图片 `resourceId` 存在且资源可用。

### 7.7.6 后端接口草案

## 7.12 当前功能块设计：学生个人知识库（开发中）

### 7.12.1 目标

学生端以个人知识库为核心：学生上传资料后，系统自动消化为个人 wiki 页（素材摘要 / 实体 / 主题），AI 助教优先基于个人知识库回答，再回退官方知识库与课程资源。

### 7.12.2 初始化

- 账号创建 / 首次登录时自动初始化个人知识库：创建学生根目录与默认分类（文档 / 图片 / 其他），生成空的 `user_wiki_profile` 学习档案。
- 学生无需理解目录结构；知识库页提供「重新初始化 / 恢复」入口，不用知识库的学生可完全忽略。
- 不使用知识库不阻塞其它功能；初始化失败不阻断登录。

### 7.12.3 上传限制

- 知识库解析仅允许文档：`md / txt / docx / pdf / ppt / pptx`。
- 图片单独维护在资源中心「图片」分类，不进入知识库文本解析；图片可预览、引用到 wiki 页。
- 每人总上传额度 300MB：上传前校验文件大小与剩余额度，列表展示已用 / 剩余空间，超出时拒绝并提示。

### 7.12.4 学生可见配置

- 学生只看到「我的学习档案」：学习目标、关键问题、感兴趣学科 / 主题、自己的术语叫法（alias）。
- 完整 schema（页面规范、ingest / lint 规则、检索优先级）属于系统层，按学段 / 年级预设，不暴露给学生编辑。

### 7.12.5 存储方案

- 当前采用服务器私有存储：文件按 `owner_id` 隔离，仅本人可见，提供下载、导出、删除。
- 文件存储抽象为独立 storage 接口，后续可切换 MinIO / S3 / WebDAV / 自建对象存储，业务层不变。
- 纯本机目录存储需要桌面客户端（Tauri / Electron）并本地化 AI 与向量检索，属于另一产品形态，暂不实现。

### 7.12.6 实施顺序

2. 个人资源消化任务：提取文本 → 分块向量化 → AI 生成 wiki 页 → 更新索引与日志。
3. AI 助教检索链路：个人 wiki 页 → 个人原文 chunk → 官方知识库 → 课程资源，回答附引用。
