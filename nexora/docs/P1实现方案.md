# Nexora P1 实现方案（账号体系闭环）

> 状态：待确认 ｜ 日期：2026-08-12 ｜ 依据：开发排期.md P1、AGENTS.md（已校准）、easymall 参考
> 目标：管理端能维护学生账号；用户端按 Codex 模式免登录浏览 + 登录/注册弹窗 + 受保护页自动弹窗

## 一、总体结构

```
管理端（admin 6061）                    用户端（web 6060）
UserInfoController  ←恢复→             StudentAccountController ←新增→
  loadDataList/getInfo/add/update/        checkCode/login/logout/register/getUserInfo/updateStage
  del/changeStatus                       GlobalInterceptor 注解 + StudentInterceptor（Web 层 AOP）
  复用 common UserInfoService            LoginUserContext（ThreadLocal 登录上下文）
前端 UserManagement 已就绪              前端 5 页改造（Codex 模式）
```

> 统一返回说明：外层永远是 `ResponseVO{status,code,info,data}`；`data` 内放业务对象（登录返回 `{token,userInfo}`，注册按 easymall 返回 `data=null`）。

## 二、管理端（先做，半天）

### 任务 A1：恢复 UserInfoController
- 路径：`nexora-java/nexora-admin/src/main/java/com/nexora/admin/controller/UserInfoController.java`
- 从旧版（66402e8）恢复，按新架构适配：
  - 继承 `com.nexora.admin.controller.ABaseController`，返回用 `getSuccessResponseVO`（与 AccountAdminController 一致）
  - 密码 MD5：用 common 新增的 `StringTools.encodeByMD5`（见公共任务）
  - 入参：list 用 `UserInfoQuery`，写操作用 `UserInfo`（@RequestBody）
- 接口契约（前端 api/user.ts 已就绪，零改动）：
  | 方法 | 路径 | 说明 |
  |---|---|---|
  | GET | /api/userInfo/loadDataList | 分页（email/stage/status/roleType 筛选） |
  | GET | /api/userInfo/getInfo | 详情（userId） |
  | POST | /api/userInfo/add | 新增（MD5、默认 status=1） |
  | PUT | /api/userInfo/update | 修改（password 空则不更新） |
  | DELETE | /api/userInfo/del | 删除 |
  | PUT | /api/userInfo/changeStatus | 启/禁用 |

### 验收 A
管理端 3001「用户管理」页：新增学生 → 列表显示 → 编辑 → 启禁用 → 删除，全部真实落库；未登录访问返回 401。

## 三、用户端后端（半天）

### 任务 B1：公共 Token 工具（复用，不重复实现）
- 新增 `nexora-common/.../component/TokenManager.java`：
  - `@Component`，`@Value("${login.token-secret:nexora-default-token-secret}")`
  - `String generateToken(String userId)` = sha256(userId + secret)（与 admin 同款）
- `AccountAdminBiz` 改为注入 TokenManager（删掉私有 generateToken/sha256Hex）
- web yml 增加 `login.token-secret`（与 admin 同默认值/同一环境变量 NEXORA_TOKEN_SECRET）

### 任务 B2：公共 MD5 工具
- `nexora-common/.../utils/StringTools.java` 增加 `public static String encodeByMD5(String str)`（参考 easymall）
- 注册/登录/管理端新增用户统一用它

### 任务 B2b：验证码公共能力（Redis 存储，不需要改表）
- `Constants` 增加 `REDIS_KEY_CHECK_CODE` 前缀；`RedisComponent` 增加：
  - `saveCheckCode(code)` → 生成 UUID key，TTL 10 分钟，返回 key
  - `getCheckCode(key)` / `cleanCheckCode(key)`
- 依赖：web pom 引入 `com.github.whvcse:easy-captcha`（parent 已管理版本 1.6.2，ArithmeticCaptcha 算术验证码，参考 easymall）

### 任务 B3：登录上下文（ThreadLocal）
- 新增 `nexora-common/.../utils/LoginUserContext.java`（或放 web 模块？AGENTS 说公共能力下沉 common，登录上下文两端都要用 → common）
  - `set(TokenUserInfoDTO)` / `get()` / `remove()`
- 拦截器写入，Controller 读取，请求结束清理（afterCompletion）

### 任务 B4：StudentAccountController
- 路径：`nexora-java/nexora-web/src/main/java/com/nexora/web/controller/StudentAccountController.java`（包名注意：web 实际包是 com.nexora，但 AGENTS 分层建议端内用子包；当前 web 根包是 com.nexora，Controller 可放 `com.nexora.controller`）
- 接口（登录/注册带验证码，参考 easymall）：
  | 方法 | 路径 | 说明 |
  |---|---|---|
  | GET | /api/studentInfo/checkCode | 生成算术验证码 → {checkCodeBase64, checkCodeKey}（公开） |
  | POST | /api/studentInfo/register | 注册：username/email/password + checkCodeKey/checkCode → 校验验证码 → 默认 stage=PRIMARY_LOW、roleType=1、status=1、MD5；email 唯一；成功返回 data=null（参考 easymall） |
  | POST | /api/studentInfo/login | 登录：email+password + checkCodeKey/checkCode → 校验验证码 → 校验状态 → token(派生) → Redis 存 1 条 → 返回 {token,userInfo} |
  | POST | /api/studentInfo/logout | 退出：删 Redis token |
  | GET | /api/studentInfo/getUserInfo | 当前登录信息（拦截器上下文） |
  | PUT | /api/studentInfo/updateStage | 修改学段（方案 B：我的页可改） |
- 复用 `UserInfoService.findByEmailAndPassword` / `getUserInfoByEmail`
- 返回 VO：`StudentLoginVO { token, userInfo: TokenUserInfoDTO }`（web 模块 dto/vo 包）

### 任务 B5：@GlobalInterceptor 注解 + StudentInterceptor（参考 easymall）
- 新建注解 `com.nexora.annotation.GlobalInterceptor`：`boolean checkLogin() default false`（可标方法/类）
- 新建 `StudentInterceptor`（HandlerInterceptor）：
  - 拦截器内通过 `HandlerMethod.getMethodAnnotation(GlobalInterceptor.class)` 判断：
    - 无注解或 `checkLogin=false` → 放行（公开接口：checkCode/register/login 等标 `@GlobalInterceptor` 或 `@GlobalInterceptor(checkLogin=false)`）
    - `checkLogin=true` → 校验 header `studentToken` → 无效抛 `BusinessException(CODE_401)` → 通过后写 `LoginUserContext`
  - 兜底：白名单路径（/error）直接放行
- 新建 `WebMvcConfigurer` 注册拦截器（web 端目前没有）
- 说明：这就是“AOP 切面拦截需要登录的接口”的 Spring MVC 实现（与 easymall 一致）

### 验收 B
curl 注册 → 登录 → getUserInfo → updateStage → logout；未登录访问受保护接口返回统一 401。

## 四、用户端前端（1 天）

### 任务 C1：路由改造（公开页 + 受保护页）
- `router/index.tsx`：
  - 删除强制 `AutoLogin` 包裹（AutoLogin 组件保留用于“有 token 恢复用户信息”）
  - 公开页：/ai-tutor、/coding 直接可访问
  - 受保护页：/learning-path、/course-material、/profile 用 `<ProtectedRoute>` 包裹
- 新增 `components/layout/ProtectedRoute.tsx`：
  - 已登录 → 渲染 children
  - 未登录 → 打开全局登录弹窗（uiStore）+ 渲染空骨架；登录成功（token 变化）自动渲染 children → 用户落在原页面

### 任务 C2：全局登录弹窗状态
- 新增 `stores/ui.ts`：`{ loginModalOpen, openLoginModal(), closeLoginModal() }`
- request.ts 响应拦截器：code===401 → clear 登录态 + `openLoginModal()`（学生端，不跳转）

### 任务 C3：登录/注册弹窗组件
- 新增 `components/auth/LoginModal.tsx`：
  - 登录表单：邮箱 + 密码 + 验证码 + 登录按钮；底部「没有账号？去注册」
  - 注册表单：用户名 + 邮箱 + 密码 + 确认密码 + 验证码；底部「已有账号？去登录」
  - 验证码：进入弹窗/刷新时调 `/studentInfo/checkCode` 显示图片；点击图片刷新
  - **注册成功自动登录（参考 easymall：register 返回 data=null，前端成功后自动调 login 完成登录）**
  - 成功后 closeLoginModal
- 新增 `api/auth.ts`：`studentCheckCode()`、`studentRegister(params)`

### 任务 C4：左下角登录入口（改造 MainLayout 底部 user-section）
- 未登录：显示「登录」按钮 → openLoginModal()
- 已登录：头像/昵称 + Dropdown（个人中心 → /profile、退出登录 → studentLogout + clear）

### 任务 C5：AI 助教发消息前置检查
- ai-tutor 页发送消息前：未登录 → openLoginModal() 并拦截发送（不发 401 请求）
- 登录后用户点发送 → 正常对话（P3 才接真实对话，P1 先做“未登录弹窗”逻辑）

### 任务 C6：我的页（profile）
- 展示用户信息（头像/用户名/邮箱/学段）
- 学段编辑：下拉选学段 → 调 updateStage → 更新 store

### 验收 C（联调，用户手动过一遍）
1. 未登录打开 /ai-tutor、/coding 正常浏览
2. 未登录点左侧「学习路径」→ 自动弹登录弹窗 → 登录 → 进入学习路径页
3. 左下角「登录」→ 弹窗登录 → 变为头像/昵称 → 下拉（个人中心、退出登录）
4. 注册新账号 → 自动登录成功
5. 管理端能看到新注册学生（默认小学低年级）
6. 退出 → 未登录态 → 再访问受保护页重新弹窗
